# System Architecture & Backend Handover

## 1. Data Models & Collections

This section maps out the required database tables/collections based on our existing Dart Models.

### `users` Collection
- **id** (String): Unique user document ID.
- **userNumber** (Int): Sequential number for user IDs.
- **name** (String): Full name.
- **role** (String): `admin`, `instructor`, or `student`.
- **searchKeywords** (Array of Strings): Segmented array for Firestore search.
- **Admin/Instructor fields**: `email`, `phoneNumber`, `address`, `assignedLevels` (Instructor only).
- **Student fields**: `levelId`, `studentNumber`, `username` (English-only), `pinCode`, `lastActive` (Timestamp).

### `groups` Collection
- **id** (String): Unique group document ID.
- **serialNumber** (Int): Sequential group number.
- **name** (String): Group name (can be English or Arabic).
- **instructorIds** (Array of Strings): Array of instructor user references.
- **createdAt** (Timestamp).
- **students** (Array of Objects): Embedded `GroupStudentEmbed` objects to optimize local reads (`id`, `name`, `level`, `pin`, `lastActive`).

### `curriculum` Collection
- **id** (String): Level/Curriculum ID.
- **name** (String): Level name.
- **weeks** (Array of Objects): Embedded weeks, containing `items` (Array of `CurriculumItem`).
  - **CurriculumItem**: `id`, `type` (`material`, `assignment`), `title`, `content`, `searchTags`, `visible`, `isActive`, `deadlineText`, `imageUrl`.
  - **deltaJson** (String): **CRITICAL** - Stores rich text content generated by Quill Editor as a stringified Delta JSON.

### `assignments` Collection
- **id** (String): Unique assignment document ID.
- **title** (String): Assignment title.
- **type** (String): `central` (from Curriculum) or `custom` (created by instructor).
- **isActive** (Boolean).
- **groupId** / **groupName** (String): Reference to the assigned group.
- **instructorId** (String): Reference to the assigning instructor.
- **pendingCount** / **gradedCount** (Int): Denormalized counters for submission statuses.
- **createdAt** / **deadline** (Timestamp).
- **textContent** (String): Plain text content.
- **assignmentType** (String): `text` or `multipleChoice`.
- **choices** (Array of Strings): Required for `multipleChoice`.

### `submissions` Collection
- **id** (String): Unique submission document ID.
- **assignmentId** (String): Reference to the assignment.
- **studentId** (String): Reference to the student who submitted.
- **submittedAt** (Timestamp).
- **answer** (String): Student's plain-text answer (no rich text or file uploads).
- **selectedChoice** (String): For multiple choice assignments.
- **status** (String): `pending`, `correct`, or `incorrect`.
- **feedback** (String): **CRITICAL** - Instructor feedback is stored as a stringified Delta JSON generated by Quill Editor.

## 2. Role Management

Roles (`admin`, `instructor`, `student`) are currently mocked but strictly gate the UI access and capabilities:
- **Admin**: Has global access to curriculum, users, and system settings. Admins **cannot** see individual student submissions. Admins manage the central curriculum templates.
- **Instructor**: Has access to their assigned groups and assignments. Instructors **cannot** edit Admin templates (central assignments) but can assign them to their groups. Instructors can grade student submissions (leaving rich-text Delta JSON feedback).
- **Student**: Has access only to their assigned groups, materials, and pending assignments. They submit plain-text answers.

## 3. Repository Contracts

The UI sends specific inputs to the Data Tier (Repositories) and expects specific outputs.

- **UserRepository**:
  - `getInstructors()`, `getStudents()` -> Returns lists of users based on role.
  - `addInstructor(...)`, `updateInstructorProfile(...)`, `deleteInstructor(...)`, etc.
- **GroupRepository**:
  - `getGroups()` -> Returns all groups.
  - `createGroup(name)` -> Returns newly created `GroupModel`.
  - `addStudentToGroup(groupId, studentId, levelId, name, pin)` -> Embeds student in group.
- **CurriculumRepository**:
  - `getLevels()` -> Returns all `LevelModel` documents containing weeks and items.
  - `addMaterial(...)`, `addAssignment(...)`, `updateItem(...)` -> Modifies curriculum hierarchy.
- **AssignmentRepository**:
  - `getInstructorAssignments()` -> Returns `List<AssignmentModel>`.
  - `addCentralAssignment(id, title, content)` -> Copies a central curriculum item to the instructor's assignment list.
  - `addInstructorAssignment(title, deadline, textContent, type, choices, groupId, groupName)` -> Creates a custom assignment.
- **SubmissionRepository**:
  - `getSubmissions()`, `getSubmissionsByAssignment(id)` -> Returns `List<SubmissionModel>`.
  - `addSubmission(...)` -> Student submits an assignment.
  - `gradeSubmission(submissionId, status, feedback)` -> Instructor grades a submission, storing Quill `feedback`.

## 4. Business Logic & Routing Rules

Strict architectural rules enforce the separation of concerns and user flows:
- **Assignment Creation Flow**:
  - Instructors assign **central** templates using a simple dialog modal (Select Group, Level, Deadline).
  - Instructors create/edit **custom** assignments using the full-screen Quill Editor (`AssignmentEditorScreen`).
- **Assignment Types**:
  - `central`: Sourced from the Curriculum, immutable body/content by the instructor.
  - `custom`: Sourced by the instructor, fully mutable.
- **Rich Text Handling**:
  - Only Instructors and Admins have access to the Quill Editor.
  - Their content (Curriculum items, Custom Assignments, Submission Feedback) is serialized and stored as `deltaJson` (String).
- **Submissions**:
  - Strictly text-based or multiple-choice. No file uploads.
  - Submissions are linked to specific `assignmentId` and `studentId`.
